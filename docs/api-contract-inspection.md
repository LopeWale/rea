# API contract inspection

`inspect_api_contract` reads one local OpenAPI 3.0.x or 3.1.x document, in JSON
or YAML, and returns the API surface it declares in REA's normal observation,
inference, and unknown structure. Both CLI and MCP use the same workflow. It
reads only the file you name, resolves no remote references, and makes no
network requests.

Use it when a service's specification is available but its servers or UI are
not: SDK repositories generated by tools such as Stainless or OpenAPI Generator
usually point at the exact document they were built from, vendor documentation
sites often publish one, and archived copies survive after a product changes.
The result gives the entity model, state machines, asynchronous jobs, and
quota semantics to confirm later against observed traffic with
`inspect_web_page`, `capture_browser_scenario`, or `fetch_web_scripts`.

## Inspect

```sh
rea inspect-api-contract /analysis/vendor-openapi.yml --json
rea inspect-api-contract /analysis/vendor-openapi.json --no-include-schema-properties --json
```

MCP uses `inspect_api_contract` with an absolute `contract_path` and optional
`include_schema_properties` (default true). The flag only trims the property
records from the output; inferences, unknowns, and reference counts are always
computed from the whole document.

Limits and rejections:

- JSON documents up to 32 MiB and YAML documents up to 8 MiB. YAML is parsed
  synchronously in memory and expands several times over, so its cap is lower
  to keep the MCP process within a 1 GiB heap. Larger files are rejected with
  reason `limit` before parsing.
- Only `openapi: 3.0.*` and `3.1.*` are read. Swagger 2.0 and OpenAPI 3.2, which
  adds `query` operations and `additionalOperations` that this inspector does
  not read, are rejected with reason `unavailable` and a message naming the
  version. A document whose root is not an object, or that is not valid JSON,
  YAML, or UTF-8, is rejected with reason `format`.
- YAML is parsed with the library defaults: at most 100 alias expansions, and
  duplicate mapping keys reported. A duplicate key keeps its last value, as
  `JSON.parse` would, and is listed under `unknowns` with its line and column.

## What is observed

- `document`: format, `openapi` version, title, version, description. Numeric
  scalars where the specification requires strings (an unquoted `3.1`) are
  coerced to text and reported under `unknowns`.
- `servers`: URLs, descriptions, and server variables with their defaults and
  enums.
- `security_schemes` and `global_security`: every declared scheme with its
  type, HTTP scheme, bearer format, API-key location and parameter name,
  OpenID Connect URL, and OAuth flows with their URLs and scope names, plus the
  document-level security requirements as `{scheme, scopes}` pairs.
- `operations`: one record per method and path, sorted by path, with the
  operation id, summary, tags, deprecation flag, effective `servers` when the
  path item or operation overrides the document list, merged parameters,
  request body media types and schema references, every response status as
  written (including `default` and ranges such as `2XX`) with its header names,
  media types, and schema references, and operation-level security (`null`
  inherits the document default, `[]` disables it).
- `schemas`: every component schema with its type or composition keyword, a
  component-level reference when the schema is an alias, `additionalProperties`
  policy, required list, `const`, enum values as JSON, and each top-level
  property's type, format, reference, array item type or reference, enum,
  nullability, bounds, default, and description. Each schema also lists every
  reference reachable inside it, with the JSON pointer where it occurs
  (`#/allOf/1`, `#/properties/items/items`, `#/additionalProperties`).

Parameters merge path-level and operation-level declarations by location and
name; the operation wins, header names compare case-insensitively, and the
reserved `Accept`, `Content-Type`, and `Authorization` header parameters are
skipped and reported, as the specification requires. A path parameter is
always `required`. Reference chains inside `#/components/parameters`,
`requestBodies`, and `responses` are followed with a visited set; schema
references are returned as bare component names.

## What is inferred

These are heuristics over names and status codes, returned under `inferences`
so they cannot be mistaken for declared facts:

- `namespaces`: path prefixes at depth 2 and 3 shared by at least two
  operations, such as `/api/v1` and `/api/v1/public`.
- `status_enums`: enum-valued top-level properties whose name ends in status,
  state, or phase, which usually describe a resource's lifecycle. Enums inside
  composition members are not flattened and so are not scanned.
- `async_indicators`: operations declaring a 202 response (which the server
  might or might not act on later), and GET operations whose response schema
  carries a status enum, which usually means the caller polls until a terminal
  state.
- `schema_references`: the reference graph between component schemas, one
  edge per resolved reference with its JSON pointer.
- `quota_statuses`: operations declaring 402 or 429 responses, which usually
  mark billed or rate-limited actions.

## What stays unknown

`unknowns` lists unresolved or external references with the position that
holds them, path items declared by reference, path keys that do not start with
`/`, unsupported path item fields, webhooks, operations with callbacks,
reserved header parameters, parameters that could not be normalized, duplicate
YAML keys, non-finite numbers, non-JSON scalars, and coerced numeric versions.
`completeness` counts operations, schemas, schemas whose properties are in the
output, and distinct unresolved references, so a partial picture is visible as
such.

## Interpretation and limits

The document describes what its author published. It does not establish the
server's actual behavior, authorization decisions, rate limits, undocumented
internal endpoints, or current availability, and a specification bundled with an
SDK may lag or lead the deployed service. The Evidence carries authority
`historical-reference` and confidence `observed`: the declared facts were read
verbatim from the document, and the heuristic facets are labeled inferences
inside the result rather than folded into the confidence.

## Verification

`src/domain/openApiContract.test.ts` normalizes a fixture that exercises
extension keys, non-path keys, parameter reference chains, path-level and
operation-level parameter merging, reserved headers, `content` parameters,
server overrides, response headers, `default` statuses, composition and
`additionalProperties` references, an alias schema, 3.1 null types, `const`,
JSON enum values, non-finite bounds, numeric scalars, Swagger 2.0 and OpenAPI
3.2 rejection, and the property-output flag.
`tests/boundary/filesystem/apiContractInspection.test.ts` runs the service on
YAML and JSON files, detects the format from content, and checks the typed
rejections for relative paths, missing files, invalid YAML, Swagger 2.0,
non-UTF-8 bytes, duplicate keys, a BOM, a pre-aborted signal, and a YAML file
above its byte limit.
